# 안전교육 시험 시스템 — 적용 안내

수정한 소스와 서버 기능을 묶은 패키지입니다. 운영 사이트에는 아직 반영하지 않았습니다. **index.html만 교체하거나 Netlify Drop에 정적 파일만 올려서는 서버 검증이 작동하지 않습니다.** 서버 기능까지 함께 배포해야 합니다.

기존 화면과 3종 시험, 20문항·30분·60점 합격, QR 접속, 결과 조회와 엑셀 다운로드를 유지했습니다. 기존 기본 문제 239문항도 그대로 서버로 이동했습니다. 기존 문항의 안전 기준·정답 자체를 새로 감수한 것은 아닙니다.

## 1. 먼저 확인할 것

- 현재 Netlify 프로젝트와 Firebase 프로젝트 `hdoexam`의 관리자 권한이 필요합니다.
- 기존 Firebase Realtime Database를 백업합니다. 기존 결과 경로는 `cert_v6`입니다.
- 새 서버는 `exam_v2`, 요청 제한은 `exam_limits`에 저장합니다. 기존 결과는 `cert_v6`에서 함께 읽습니다.
- 기존 브라우저의 localStorage에만 남은 오프라인 결과는 자동 이전되지 않습니다. 그 브라우저에서 기존 엑셀 내보내기로 따로 보관합니다.
- 실제 DB 자격증명이나 관리자 비밀번호를 HTML·Git 저장소·채팅에 넣지 않습니다.

## 2. Netlify 환경변수 설정

Netlify의 기존 프로젝트에서 환경변수를 설정합니다. 서버 Functions에 적용되도록 설정하고, 변경 후 새로 배포합니다.

| 이름 | 넣을 값 |
|---|---|
| `PUBLIC_ORIGIN` | `https://mellow-brioche-444e89.netlify.app` — 끝에 `/` 없이 정확한 운영 주소 |
| `FIREBASE_DATABASE_URL` | `https://hdoexam-default-rtdb.firebaseio.com` |
| `FIREBASE_SERVICE_ACCOUNT_JSON` | Firebase 프로젝트 설정 → 서비스 계정에서 발급한 서비스 계정 JSON 전체. 해당 DB 접근 권한이 있는 계정 사용 |
| `ADMIN_PASSWORD` | 새 관리자 비밀번호, 12자 이상. 기존 HTML의 관리자 비밀번호는 폐기 |
| `SESSION_SECRET` | 무작위 32자 이상 비밀 문자열. 예: 로컬 Node에서 `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`로 생성 |

서비스 계정 JSON은 Netlify의 비밀 환경변수로만 저장합니다. 줄바꿈은 JSON의 `\n` 표기를 포함한 원본 형식을 유지합니다. 서비스 계정은 이 시험 DB를 읽고 쓰는 데 필요한 권한만 부여합니다.

## 3. Firebase 직접 접근 차단

패키지의 `database.rules.json`은 **시험 전용 데이터베이스 전체를 브라우저에서 읽고 쓰지 못하게 하는 예시**입니다. 서비스 계정으로 동작하는 서버만 접근합니다.

이 데이터베이스를 다른 앱도 쓰고 있다면 예시를 전체 덮어쓰기하지 말고 기존 규칙과 함께 검토해야 합니다. `cert_v6`, `exam_v2`, `exam_limits`가 공개되어서는 안 됩니다. 상위 경로에 `.read: true` / `.write: true`가 있으면 하위 경로의 거부 규칙으로 덮어쓸 수 없습니다. 다른 앱의 필요한 인증 규칙은 보존합니다.

기존 HTML은 브라우저에서 Firebase에 직접 접속하므로 규칙을 잠그면 기존 버전의 결과 저장은 중단됩니다. 진행 중 시험이 없는 시간에 백업 → 새 서버 배포·확인 → 규칙 적용·재확인을 진행합니다. 공개 규칙이 남아 있는 상태를 운영 완료로 간주하면 안 됩니다.

## 4. 배포 방법

권장: 이 폴더 전체를 기존 Netlify 프로젝트와 연결한 Git 저장소에 반영한 뒤 배포합니다. 저장소 최상단에 `netlify.toml`, `public`, `server`, `netlify/functions`가 놓이도록 합니다.

- 공개 디렉터리: `public`
- 서버 함수 디렉터리: `netlify/functions`
- Node: 22 이상
- 별도 빌드 명령: 없음
- 런타임 npm 의존성: 없음. QR·Excel 라이브러리는 `public/vendor`에 포함

CLI를 사용할 수 있다면 같은 폴더에서 `npx netlify-cli login`, `npx netlify-cli link`로 **기존 프로젝트**를 선택하고, `npx netlify-cli deploy --build --prod`를 실행하는 방식도 가능합니다. 다른 새 프로젝트를 만들 필요는 없습니다.

Netlify 정적 파일 드래그앤드롭만으로는 이 패키지의 함수 소스를 배포할 수 없습니다. 배포 후 Functions에 `exam` 함수가 생성됐는지 확인합니다. `server/default-bank.json`은 서버 함수에 포함되어야 하며 공개 디렉터리에 복사하면 안 됩니다.

## 5. 시험지 등록

관리자 로그인 → 시험지/문제은행 → 화기·밀폐공간·유도원 선택 → 파일 선택(여러 개 가능) → 시험지 추가.

- 지원: `.xlsx`, UTF-8 `.csv`, `.json`
- Excel/CSV 열: `문제, 보기1, 보기2, 보기3, 보기4, 정답`
- Excel/CSV 정답: **1~4**
- JSON: `[{"q":"문제","o":["보기1","보기2","보기3","보기4"],"a":0}]` 형태. `a`는 **0~3**
- Excel은 각 시트에 같은 제목 행을 넣습니다. 모든 시트의 문제를 합칩니다.
- 파일당 최대 1MB·500문항, 시험 종류당 합계 1,000문항.
- 모든 보기는 4개, 정답은 하나입니다. 그림·수식 개체·서술형은 지원하지 않습니다.
- PDF, HWP, DOCX, 스캔 이미지는 자동 추출하지 않습니다. 제공 CSV 양식으로 옮겨 등록해야 합니다.
- 원본 파일명과 파싱한 문제를 보관합니다. 원본 바이너리 재다운로드 기능은 없습니다.
- 기존 기본 문제은행을 유지하면 새로 올린 시험지와 함께 추출 대상이 됩니다. 업로드한 시험지만 쓰려면 검토 후 `기존 기본 문제은행` 항목을 삭제합니다.
- 유사도는 한국어 의미 이해 AI가 아니라 정규화된 글자 쌍 비교입니다. 비슷한 문장이라도 부정 표현·수치·정답이 다를 수 있으므로 관리자에서 그룹을 검토합니다. 기본 임계값은 75%입니다.

## 6. 시험 운영

감독 기능도 관리자 로그인 후 사용합니다. 시험 선택 시 2시간 이내의 기존 코드가 있으면 남은 유효시간 그대로 표시합니다. 재생성을 누르면 새 코드가 발급되고 이전 코드는 즉시 서버에서 거부됩니다. 만료 후 다시 생성해도 새 코드가 발급됩니다.

주의: 이번 구현은 재생성·만료 시 기존 코드로 시작한 진행 중 시험도 종료시킵니다. 응시 시작 직후 코드를 재생성하지 마세요. 시작 시점에 유효기간이 10분 남았다면 최대 응시 시간도 10분입니다. 새 회차는 재생성한 뒤 시작하는 것이 좋습니다.

브라우저는 진행 중 10초마다 서버 상태를 확인합니다. 이미 받은 문제를 모든 기기에서 같은 순간 원격 삭제할 수는 없지만, 이전 코드로 새 문제를 받거나 답안을 제출하는 요청은 즉시 거부/종료 처리됩니다. 이미 촬영·복사한 내용까지 회수할 수는 없습니다.

화면 이탈은 1회 경고·2회 자동 종료입니다. 페이지 종료/새로고침과 지원되는 제한 키보드 단축키는 종료 처리합니다. 통화·화면 잠금 등도 화면 이탈로 잡힐 수 있으므로 사전 안내가 필요합니다. 서버 연결에 실패하면 문제 화면을 가리고 재연결을 요구합니다.

## 7. 적용 후 필수 확인

1. 관리자 로그인, 기본 문제은행 수, 기존 합격자 조회를 확인합니다.
2. 양식 시험지를 2개 등록해 등록 수·중복 수·출제 가능 수와 삭제를 확인합니다.
3. 코드 발급 → 재생성 → 이전 코드 직접 API 요청이 거부되는지 확인합니다.
4. 실제 iPhone Safari·Android Chrome에서 QR·시험 시작·답안·제출·이탈 기록을 확인합니다.
5. 2시간 만료, 한국 시간 날짜 양끝, 엑셀 다운로드를 확인합니다.
6. 비로그인 상태에서 Firebase의 `cert_v6.json`, `exam_v2.json`, `exam_limits.json` 직접 요청이 거부되는지 확인합니다. 서비스 계정 없이 공개 조회되면 운영하면 안 됩니다.
7. 동시에 사용하는 인원 수준으로 부하를 확인합니다. 현재 단일 상태에 ETag 조건부 갱신을 적용하므로 시험/기록이 많이 누적되거나 동시 요청이 많으면 DB 구조 분리가 필요할 수 있습니다. 충돌은 8회 재시도 후 실패로 안내하며 문제를 임의로 허용하지 않습니다.

## 8. 개발 테스트

- `npm test`: 핵심 로직 및 API 테스트. 외부 Firebase는 메모리 기반 모의 서버입니다.
- `npm run dev`: **로컬 테스트 전용** 서버. 테스트 비밀번호는 `test-admin-password-only`입니다. 운영 자격증명 없이 가상 DB로 동작하며 저장 내용은 프로세스 종료 시 사라집니다. 이 서버는 절대 운영에 배포하지 않습니다.
- 브라우저 테스트: Playwright와 Chromium 설치 후 로컬 서버를 띄우고 `node tests/browser.mjs`. 필요 시 `CHROME_EXECUTABLE`로 브라우저 실행 파일 경로 지정.
- 상세 변경·테스트·보안 한계는 `IMPLEMENTATION_REPORT.md`를 확인합니다.
